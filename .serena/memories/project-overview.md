# belt: project overview (as of 2026-11-26)

- Rust CLI toolbelt, crate `belt-cli`, binary `belt`, edition 2024. Rust 1.100.0 is pinned in `mise.toml`, `Dockerfile`, CI (`.github/workflows/ci.yml`) and trunk's `clippy`/`rustfmt` entries; bump all four together.
- Ground-up rewrite of the Python package. The old Python implementation is preserved on the `python` branch (local and `origin/python`); use it as the porting reference. It had `audio`, `crypt`, `dns`, `domain`, `tls` command groups and config at `~/.config/belt/config.yaml`. None of that is ported yet.
- The only command is `belt pw [MIN_LENGTH]` (`src/pw.rs`, dispatched from `src/main.rs`; bare `belt` prints help). It prints five English BIP39 words, one to four of them uppercased, with four joiners that always mix digits and symbols from `&+.,/-=?@#^%`. The minimum is exclusive: default `pw::DEFAULT_MIN_LENGTH` = 18, the longest minimum that rejects nothing because the shortest password is 19 characters (a unit test pins this). Minimums 32–35 warn (>70% of word tuples rejected); 36 and up are refused (>95%). Short candidates are regenerated silently; stdout carries only the password.
- Deps in use: `clap` (derive), `bip39`, `rand`. Groundwork, unused so far: `ratatui`, `crossterm` (osc52), `clap_complete`, `clio`, `blake2`, `ur`, `shadow-rs`, `tera`, `tera-contrib` and the build dependency `clap_mangen`. Cargo 1.100 prints manifest "unused dependency" warnings for them; these don't fail `clippy -D warnings`. `shadow-rs` and `clap_mangen` need a `build.rs`, which doesn't exist yet.
- Canonical agent guidance is `AGENTS.md`; `CLAUDE.md` is a symlink to it. `README.md` documents `pw` and has the owner's notes on why each dependency is there.
- CI gate: `cargo fmt --check`, `cargo clippy -D warnings`, `cargo test`, release build, Docker build + smoke run, all `--locked`. `trunk check` runs the wider linter set and installs pre-commit/pre-push hooks.
- `mise.toml` wraps `cargo` in `mbx` (mr-boxington) for cached builds and has a `bump` task (`op run -- mise upgrade --bump --local`). It uses multi-line inline tables; an older commit message claimed this was invalid TOML but `mise current rust` parses it fine.
- Tutorial series `learning` in `docs/learning`. Part 1 builds `belt tag` (clap + clio + blake2 + ur Bytewords); Part 2 adds config via `confy` 2.0.0 (TOML at `~/.config/belt/config.toml`, `--config`/`BELT_CONFIG`, `belt config path|init`); Part 3 adds `BeltError` (12-variant enum, hand-written Display/Error, `caused by:` chain printed in main, no `From<io::Error>` by design), random tags via `rand` 0.10.3, and `belt mise add TOOL@VERSION` (`toml_edit` 0.25.17 format-preserving edit of `~/.config/mise/config.toml`, `[mise] chezmoi = true` routes the edit through `chezmoi source-path`/`decrypt`/`encrypt`/`apply`, line-based edit for `.tmpl` sources, `etcetera` 0.10.0 as a direct dep). The code from the parts is NOT committed to `src/`; the reader applies it.
- Part 3's "What's next" points Part 4 at `belt decent` (Part 1's command tree: chat/send/edit over an MQTT broker, file transfer modelled on Magic Wormhole's PAKE) and at how `BeltError` grows a variant for a network/client-library error.
- Research notes in Basic Memory under projects/belt: "Rust config crate survey for belt (October 2026)" and "chezmoi integration for belt mise (October 2026)" (verified chezmoi 2.73.0 behaviour, toml_edit decor gotcha, captured compiler messages, mise global config facts).
- The owner's real mise config is chezmoi-managed as `dot_config/mise/config.toml.tmpl` (template, not encrypted), with `[tools]` once and `{{- if eq .chezmoi.os "darwin" }}` blocks nested below it. Never run chezmoi write commands against it from a session; test with `HOME=/tmp/...` isolation.
